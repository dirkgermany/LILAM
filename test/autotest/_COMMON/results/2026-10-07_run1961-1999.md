## Befunde

### 1. Rule Sets mit leerem Wert (`"value": ""`) werden abgelehnt (produktionsrelevant)

REGELN und REGELN_LAST brechen beim Laden ihres Rule Sets ab:

```
ORA-20130: LILAM: rule set LT_REGELN v1 (group LT) rejected: rule #14 (id ?): "condition.value" is not a text or number, or longer than 4000
```

Regel #14 ist `PR-01` (`ON_START` mit `"value": ""`). Nachgestellt mit `CHECK_RULE_SET`: dieselbe Regel ohne `value` ist gültig, mit `"value": ""` nicht.

**Ursache (belegt):** `unreadable` in `lilam.pkb` (Zeile 6162) erkennt einen leeren Text daran, dass `JSON_ELEMENT_T.to_clob` den Wert `""` (Länge 2) liefert. Unter Oracle 23.26 liefert `to_clob` für `""` einen leeren Text (Länge 0); geprüft mit `json_object_t.parse('{"value":""}').get('value').to_clob`. Damit gilt jeder leere Text als „nicht lesbar“.

**Wirkung in Produktion:** Jedes Rule Set mit `"value": ""` wird von `SERVER_UPDATE_RULES` abgelehnt; ein Server, der es beim Start liest, läuft ohne Regeln (nur ein Eintrag in `LILAM_LOG_INTERNAL`). Leere Werte sind für `ON_START`, `ON_STOP`, `ON_EVENT`, `ON_UPDATE` üblich, auch in `rules/metro_rule_set_v1.json` (SEQ-005, SEQ-006) und in der Doku. Das U-Bahn-Beispiel `SUBWAY_PROD` ist nicht betroffen.

**Korrektur (von Dirk freigegeben, umgesetzt):** In `unreadable` Länge 0 und 2 als „fehlt“ werten:

```sql
AND NOT (l_val.is_string AND nvl(dbms_lob.getlength(l_val.to_clob), 0) IN (0, 2)); -- "" counts as missing
```

Danach lehnt `CHECK_RULE_SET` `"value": ""` nicht mehr ab, eine leere `action` weiterhin („action missing“). REGELN_LAST bestand danach (1998).

### 2. REGELN IS-03: Testgruppe ohne aktives Rule Set (Testfehler, kein Produktfehler)

Run 1997: `IS L-01 IS-03 direkt nach dem Update noch Version 1 – Alerts 0, erwartet 1`. IS-03 erwartet, dass die Gruppe `LT_RG_IS2_<run>` beim ersten Prozess Version 1 lädt; der Test aktiviert für diese Gruppe aber nie Version 1 (nur `l_is_grp` wird per `SERVER_UPDATE_RULES` aktiviert). Der erste Prozess fand also kein aktives Rule Set, die Session prüfte erst nach 15 s wieder. LILAM verhielt sich wie dokumentiert. Die Prüfung war neu (B6, Commit b91a9aa) und lief heute zum ersten Mal.

**Korrektur:** In `lt.t_regeln` nach `lilam.server_update_rules(l_is_grp, c_set, 1);` auch `lilam.server_update_rules(l_is_grp2, c_set, 1);`. Danach bestand REGELN mit 86 von 86 Prüfungen (1999).

## Fazit

Alle 34 Tests bestehen mit dem aktuellen Stand. Gefunden wurde ein produktionsrelevanter Fehler der neuen Prüfung beim Laden: Leere Werte (`""`) wurden abgelehnt, Server mit solchen Rule Sets liefen ohne Regeln. Die einzeilige Korrektur ist umgesetzt, ebenso eine fehlende Aktivierung im Test REGELN (IS-03). Sonst keine Fehler in Client-Jobs und keine unerwarteten Einträge in `LILAM_LOG_INTERNAL`.
